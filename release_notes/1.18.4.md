# Vibepollo 1.18.4 - 2026-07-25

Notice: Vibepollo may trigger false-positive antivirus alerts.

Notice: builds from this fork are not code-signed, so Windows SmartScreen reports an unknown
publisher on first run. Choose "More info" then "Run anyway" to continue.

This release contains everything in Vibepollo 1.18.3 plus the changes below.

## Changes
- Merged upstream Vibepollo up to 1.18.1-stable.2. The Playnite features this fork adds are unchanged; everything else below comes from upstream.
- Added adaptive smoother capture for virtual displays: the recommended mode runs the desktop at normal refresh and switches to 4x while a game is active, with disabled automation and the legacy fixed-2x mode still available.
- Added per-client virtual-display HDR peak calibration from 400 to 2000 nits and per-client Windows scaling, keeping display identity, HDR profiles, and encoder metadata aligned with each client.
- Reduced virtual-display stream startup latency by skipping redundant HDR transitions and settle waits on displays that are already verified, without giving up the full recovery path when it is needed.
- Localized virtual capture, settings, application editing, Lossless Scaling, WebRTC, dashboard, and save-state workflows across the supported languages. The "Skip games hidden in Playnite" strings this fork added are now translated as well.
- Updated the bundled Playnite extension to 0.4.13, which carries both this fork's library reporting and upstream's launch handling.

## Fixes
- Fixed the Playnite extension auto-update never running when the installed version had a lower-numbered but longer patch component. Versions were compared as raw text, so an installed 0.4.8 counted as newer than the packaged 0.4.13 and the pre-launch update was skipped, while the Playnite tab still offered the update.
- Prevented encoded WebRTC video corruption and long decoder recoveries by isolating encoder state per session, preserving frame dependency chains, and resuming from a decodable keyframe after drops.
- Kept browser-stream latency bounded when the capture rate diverges from network or receiver capacity, and stopped resetting streams whose frame cadence is intentionally sparse.
- Released idle or abandoned WebRTC capture and encoder resources without disturbing active RTSP streams, so a lost browser disconnect no longer blocks resumes or shutdown.
- Fixed races in virtual display activation, restore, reconnect, and session handoff, and stopped adaptive refresh from reapplying in a loop.
- Recovered temporary per-client displays through sleep, host restarts, and headless resume without touching displays owned by another process.
- Forwarded the Vibepollo session environment through Playnite launches, including fullscreen ones, preserved launches across live plugin updates, and restored Playnite's original environment on disconnect.
- Honored explicit client HDR requests when 10-bit SDR is preferred, restored RTX HDR brightness above 1000 nits, and kept initial and live HDR peak metadata synchronized for native NVENC HEVC and AV1 streams.
- Recovered stream startup when RTSS hooks stop responding, stopped the frame limiter from replaying stale values on reconnect, and applied global, application, and client overrides in the right order.
- Removed stale virtual display driver packages reliably during upgrades and restaged changed payloads without requiring a reboot.
- Restored the pre-launch screen saver setting after streaming pauses or stops, and surfaced paired-client authentication failures instead of hiding existing clients.

## Known issues
- The Windows Graphics Capture optimizations upstream shipped in 1.18.1-beta.2 were reverted after reports of stutter, latency, and encoder timeouts, so capture keeps the earlier conservative copy path.

# Vibepollo 2.2.0

These release notes cover the stable 2.2.0 releases, from the original stable release through this update.

## 2.2.0

Notice: Vibepollo may trigger false-positive antivirus alerts.

Notice: builds from this fork are not code-signed, so Windows SmartScreen reports an unknown
publisher on first run. Choose "More info" then "Run anyway" to continue.

Streams that end cleanly, a sharper default encode, and loss-aware FEC for clients that ask for
it. Several fixes also come from upstream.

### Changes

- A stream whose game quit now ends cleanly on the client. The host flushes the termination
  packet before tearing the session down, so the client reports that the app quit instead of a
  bare "Connection terminated: -1" (seen intermittently on the Thor).
- Playnite streams end sooner after the game closes. Once Playnite confirms the game stopped, the
  launcher exits after 2 s instead of 15 s.
- The installer removes a legacy PowerShell Playnite connector left next to Playnite's program
  files, and a launch replaces it. Both connectors used to load and fight over the same pipe,
  which is what made a stream linger after the game quit.
- NVENC now defaults to preset P4 with spatial AQ, for visibly better image quality at the
  bitrates a handheld gets over Wi-Fi. A frame-budget guard steps the preset down at session
  start when the resolution and frame rate would not fit (for example 4K120 on one NVENC
  engine falls back to P1). Set `nvenc_preset`, `nvenc_spatial_aq` or
  `nvenc_frame_budget_guard` to override it, globally, per app or per client.
- Dynamic FEC, for clients that opt in: the client sends loss summaries and the host adapts the
  parity to the actual loss, taking it out of the `/bitrate` budget. Clients that do not opt in
  keep the fixed FEC exactly as before. See `docs/dynamic-fec.md`.
- Input boost, off by default (`input_activity_boost`): right after an input on a static screen
  the encoder sends duplicate frames at the stream's framerate for a short window, so clients
  that hold the newest frame show the response one frame later instead of one idle interval
  later. It applies to every client once enabled, and not to native AMF or PyroWave.
- Keyboard hints, off by default (`focus_hints`, Windows): a client that asks is told when a text,
  numeric or password field takes focus, so a handheld can raise the on-screen keyboard by
  itself.
- A client with only view permission can no longer terminate the running app through a crafted
  terminate request. Ported from ApolloVibe.
- SudoVDA: the virtual display is matched by adapter LUID as well as target id, so a stream
  cannot pick another adapter's display or fail with "matched multiple SudoVDA devices".
  Ported in part from ApolloVibe.
- From upstream (RamazanKara): AMD AMF low-latency fast path, with an attributed rollback to the
  native encoder if initialization fails.
- From upstream (Chase Payne): installer fixes for driver choices that survive upgrades, newer
  self-signed display drivers and bundled gamepad detection; the updater checks this fork's
  releases.

### Known issues

- When the game loses focus, telemetry stops and the client panel goes blank for a moment
  until the game is back in the foreground.
- SuccessStory usually refreshes a game's achievements only when the game closes, so unlocks
  can show up on clients after the session rather than during it.
- IGDB metadata has not yet been exercised against a live account.
- Releases from this fork are unsigned.

## Arch Linux and CachyOS

Download [`vibepollo-2.2.0-1-x86_64.pkg.tar.zst`](https://github.com/DanieleS/Vibepollo/releases/download/2.2.0/vibepollo-2.2.0-1-x86_64.pkg.tar.zst) and install it with:

```bash
sudo pacman -U ./vibepollo-2.2.0-1-x86_64.pkg.tar.zst
```

Managed virtual displays require Linux 6.16 or newer. If matching headers are missing, the package prints the exact `sudo pacman -S --needed <kernel-package>-headers` command for the running kernel. Run it, then retry the driver setup:

```bash
sudo /usr/libexec/vibeshine/vibeshine-drm-install install
```

Or let the installer script handle headers, the package, and the firewall:

```bash
curl -fsSLO https://raw.githubusercontent.com/DanieleS/Vibepollo/2.2.0/scripts/linux_install.sh
sudo bash linux_install.sh --version 2.2.0
```

See the [full Linux installation guide](https://github.com/DanieleS/Vibepollo/blob/2.2.0/docs/linux/install.md).

# Vibepollo 2.0.0-beta.3.2 - 2026-09-18

Notice: Vibepollo may trigger false-positive antivirus alerts.

Notice: builds from this fork are not code-signed, so Windows SmartScreen reports an unknown
publisher on first run. Choose "More info" then "Run anyway" to continue.

This release fixes the metadata settings reported in 2.0.0-beta.3.1. Everything else in that
release is unchanged.

## Fixes
- Fixed the client secret never being stored or read. With no explicit path in the
  configuration, the secret file resolved to the configuration directory itself rather than to
  a file inside it, so saving it failed and reading it silently returned nothing. Setting the
  secret from either web UI, or dropping the file in by hand, both did nothing.
- The settings now show the exact path the secret is read from and written to, so a secret
  that is not being picked up is visible rather than something to deduce.
- Fixed the game metadata card in the new web UI rendering unstyled: an oversized heading, a
  bare icon, no card outline and plain browser checkboxes. It was built from class names that
  belong to the integrations page itself and therefore styled nothing from inside a component.
- Fixed the same mistake in reverse on the classic web UI, where the metadata tab's buttons
  and inputs used classes from a framework that interface does not use, and rendered as plain
  text.
- The Twitch client secret now sits directly below the client ID it belongs to. In the new web
  UI a single Save writes both; the classic UI keeps an explicit Save for the secret, because
  that page saves every other field as you type and a secret should not be.
- Failing to store the client secret now reports which step failed and on which path, instead
  of a flat "Could not store the IGDB secret". The location is also resolved directly rather
  than relying on the configuration carrying a default.

## Known issues
- IGDB metadata still has not been exercised against a live account.
- Releases from this fork are unsigned.
